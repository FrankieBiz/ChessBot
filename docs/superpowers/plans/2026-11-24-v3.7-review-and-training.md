# ChessBot 3.7 review and training plan

**Goal** · Turn the 3.6 gap audit into a more complete offline review. Compare ChessBot to Chess.com on observable capabilities and measure quality against independent reference data.

**Architecture** · Keep the existing full-network Stockfish review, opening lookup, and practice deck. Add a bundled opening explorer, bounded per-move verification, board coaching derived from legal continuations, and performance context from calibrated peers or comparable local reviews.

**Stack** · Browser extension, JavaScript modules, chess.js, Stockfish.js, Node's test runner, Playwright, and reproducible public-data benchmarks.

## 1. Opening explorer and coverage

- [ ] Expand the CC0 opening sample in `scripts/build-opening-book.mjs`. Preserve named lines and exact position-and-move matching. Require repeated evidence across independent source dates for empirical Book lines.
- [ ] Add a compact explorer index and a lookup in `opening-explorer.js`. Include sample size, SAN, White wins, draws, and Black wins. Use hash-pinned sources and keep the extension offline.
- [ ] Compare 3.6 and the expanded book on a separate sample by ply. Record results, download commands, size, and limitations in `docs/benchmarks.md` and `research/`.
- [ ] Add an opening review panel to `review.html` and `review.js`. Show the first move absent from the repertoire and let the player preview an alternative on the board. Report a later transposition back into the book when it occurs.
- [ ] Verify named lines, transpositions, nonstandard starts, and legal alternatives. Run the browser flow for an opening where the first departure is known.

## 2. Targeted engine verification

- [ ] Add `deepCheckDecision` to `analysis.js` and explicit bounded nodes in `engine.js`. Compare the played move and alternatives at a common deeper search depth. Keep incomplete results visible as provisional.
- [ ] Expose actual comparison depth and whether a grade was based on one pass or corroborated. Implement per-move Deep Check in `review.js` with isolated worker state and stale-result guards.
- [ ] Test mate and forced lines, insufficient evidence, a grade that changes, and navigation while the check runs. Keep the quick review and the saved practice record internally consistent.
- [ ] Run a paired full-game audit spanning time controls and opening, middlegame, and endgame decisions. Report agreement, confidence coverage, and node cost. Keep the default search policy unless the evidence supports a change.

## 3. Coaching on the board

- [ ] Derive coach evidence from legal engine continuations in `coach-evidence.js`. Prefer a concrete opponent reply after the game move and identify its target or consequence. Cover quiet replies, captures, checks, mates, and stale or illegal lines.
- [ ] Add a board action next to the explanation in the existing review card. A player can see the threat and step through the reply, return to the game, then retry the decision without losing the original review.
- [ ] Verify correct board perspective, selected move, focus, and reset on navigation. Test a tactical mistake and a position without a usable continuation.

## 4. Performance context

- [ ] Evaluate a peer-relative sound-decision or loss measure with holdouts by platform, skill band, and time control. Test transfer to the same evaluations the browser will use and record supported domains and sample sizes.
- [ ] Add a pure summary in `performance.js` and an original performance panel. Where the peer sample supports the result, show observed decisions beside expected decisions. Use a comparison with the player's own recent same-pool or same-time-control reviews when available. Use explicit sample sizes and handle small or unsupported samples in the UI.
- [ ] Verify per-side filtering, older saved reviews, short games, unsupported rating pools, and the model's recorded error. Keep single-game performance measured in decisions or points with a clear scale.

## 5. Release and verify

- [ ] Stage all packaged modules and set the extension and npm version to 3.7.0. Update the changelog and methodology with the measured results.
- [ ] Run `npm test`, `npm run build`, and archive integrity checks. Exercise opening exploration, Deep Check, coach reply preview, and performance in the built extension. Check Chrome and Firefox.
- [ ] Compare the shipped result to the gap audit. Report which workflows now exist, where ChessBot offers stronger offline tools, and which claims still require direct comparative data.
